# 问题解决说明 · dsh-plugin-drop

本文对应当前这台机器：`DSH_HOME=E:\dsh\home`，profile `desktop`，插件装在
`E:\dsh\home\profiles\desktop`（`dsh-plugin-drop`，`link:` 到工作区）。

---

## 0. 先做这两件事

| 动作 | 作用 | 什么时候需要 |
| --- | --- | --- |
| **刷新页面**（F5） | 让浏览器半身换成新版本（进度条、报错解释、按路径自动重试） | 每次更新后 |
| **重启 DSH** | 让宿主半身换成新版本（暂存列表、诊断日志、`/staged/delete`） | 更新后一次；平时装完插件生效也靠它 |

免重启的替代办法：设置里的「插件」页找到 `dsh-plugin-drop`，**关掉再打开**，让 HMR 重组一次；不生效就重启。

## 1. 页面现在有什么

- **进度条**：`读取拖入的文件`（按字节给百分比）→ `上传并暂存到磁盘` → `执行官方安装操作`（不确定进度，显示已用时间）→ `完成` / `已停止`。
  上传和官方操作这两个阶段没有可用的进度接口，所以用流动条 + 计时，而不是编一个假百分比。
- **实时日志**：官方操作（pnpm / Loader）的原始输出原样显示。
- **已暂存的插件包**：直接读磁盘，每条都能「安装 / 删除」。**这是凭据失效后的补救入口。**
- **环境**：profile、profile 目录、DSH home、暂存目录、诊断日志路径。
- **当前 profile 的插件**：列出依赖与插件层，非 `@deepseek-ai/*` 的可卸载。

## 2. 你的这次故障：发生了什么

从磁盘证据看（时间均为 2026-10-04 本地时间）：

| 时间 | 证据 | 含义 |
| --- | --- | --- |
| 11:39:04 | `...\plugin-drop\staged\dsh-purge\dsh-purge-master_2\dsh-purge-master\package.json` | 第一次拖入**上传并暂存成功**（3.4 MB / 104 个文件） |
| 11:40:24 | `...\staged\drop-Ox2lK7\dsh-purge-master\...` | 第二次拖入也**暂存成功**（同一个包的副本） |
| 11:44:51 | `...\staged\dsh-infinite-gen-4\package.json` | 第三次换了另一个包，同样**暂存成功** |
| 三次之后 | `E:\dsh\home\profiles\desktop\.plugin-manager\logs\` 没有新增 `operation-*`；`package.json` / `pnpm-lock.yaml` 停在 11:26:46 | **官方安装操作从未启动**——不是安装失败，而是没走到那一步 |

也就是说：**上传和暂存一直是对的，卡在「暂存成功 → 请求安装」这一步**，而且三次都一样。
最可能的原因是**暂存凭据（token）失效**——它只存在宿主进程内存里，宿主一重启就没了；
旧版本在这种情况下只弹一句**英文**错误，既不告诉你东西其实已经暂存好了，也不给补救入口，
看起来就是「无法使用」。新版本对此做了三件事：

1. 凭据失效时**自动改用暂存路径重试**（不必重新拖一次）；
2. `/state` 从磁盘列出**已暂存的插件包**，每条都能直接「安装」；
3. 全过程写进**诊断日志**，并把英文报错翻成可操作的说明。

## 3. 现在怎么把你那两份包装上

**它们都还在磁盘上，不用重新下载。** 我用同一条命令、同一套适配器实测过 dsh-purge 这个包能装成功。

- dsh-purge：`E:\dsh\home\plugin-drop\staged\dsh-purge\dsh-purge-master_2\dsh-purge-master`
- dsh-infinite-gen-4：`E:\dsh\home\plugin-drop\staged\dsh-infinite-gen-4`
- （`...\staged\drop-Ox2lK7\dsh-purge-master` 是 dsh-purge 的重复副本，可以删）

三种装法：

- 方式一：刷新页面 → 「已暂存的插件包」里点 **安装**（需要宿主半身已是新版本，即重启过 DSH）
- 方式二：页面「从本地路径或包名安装」里粘贴上面的路径 → 安装
- 方式三：等价的手工命令（PowerShell；`DSH_HOME` 必须设置，否则会报 “requires their owning home”）
  ```powershell
  $env:DSH_HOME = "E:\dsh\home"; $env:ELECTRON_RUN_AS_NODE = "1"
  & "C:\Users\Lenovo\AppData\Local\Programs\DSH NEXT\DSH NEXT.exe" --expose-internals `
    "C:\Users\Lenovo\AppData\Local\Programs\DSH NEXT\resources\app\lib\plugin-cli.js" `
    desktop add "E:\dsh\home\plugin-drop\staged\dsh-purge\dsh-purge-master_2\dsh-purge-master"
  ```
- 装完**重启 DSH** 生效。

## 4. 症状 → 原因 → 处置

| 症状 | 原因 | 处置 |
| --- | --- | --- |
| 侧栏看不到「插件安装」 | profile 还没加载这个插件 | 重启 DSH；确认 `E:\dsh\home\profiles\desktop\package.json` 的 `dsh.profile.bundles` 里有 `dsh-plugin-drop` |
| 页面提示「这个安装器无法工作」 | 宿主半身读不到 profile/上下文 | 页面会列出诊断行（`publishedContext` / `environment` / `argv`），照抄给我即可定位 |
| 拖入后长时间只有空日志、像卡住 | 旧版本没有进度显示；或官方操作在等 pnpm | 刷新页面拿到进度条；再看诊断日志里有没有 `install started` |
| 安装未开始：暂存凭据已失效 | 凭据随宿主重启失效（或响应丢失） | 新版本会自动按路径重试；否则用「已暂存的插件包」列表点安装 |
| 安装失败（退出码 ≠ 0） | pnpm/Loader 的真实报错 | 看页面日志原文与 `operation-*/pnpm.log`；常见：包没有 `dsh.bundle.patch`（只会作为普通依赖）、版本不兼容、网络/镜像问题 |
| 「已暂存的插件包」显示“宿主半身还是旧版本” | 宿主半身是旧版（页面已刷新过） | 重启 DSH |
| 从别的设备打不开这个页面 | 安装器只服务本机回环请求（安全设计） | 在运行 DSH 的机器上操作；桌面端“浏览器访问”关闭时，外部浏览器一律 403 |
| 文件夹太大拖不动 | 上传上限 64 MiB（base64 前） | 用绝对路径安装，不经过上传 |
| 装完没生效 | 新插件层需要重新加载 | 重启 DSH；HMR profile 会自动重组 |
| 想撤掉某个插件 | — | 页面「当前 profile 的插件」里卸载；或 `dsh plugin --profile desktop remove <名字>` |

## 5. 页面上的报错会自己解释

宿主返回的是英文诊断，页面会把它翻成一句可操作的说明，并保留原始英文（方便报错时贴给我）：

| 页面说明 | 含义与处置 |
| --- | --- |
| 暂存凭据已失效……请在「已暂存的插件包」里点「安装」 | token 随宿主重启失效；包还在磁盘上 |
| 宿主半身读不到当前 profile | 重启 DSH；仍不行就把「环境」区块发我 |
| 找不到官方安装适配器 | 这台 DSH 安装不完整，缺少 `lib/plugin-cli.js` |
| 上传超过上限 | 改用绝对路径安装 |
| 拖入的内容不是插件包 | 需要直接包含 `package.json` |
| 请求没完成（超时或被中断） | 重试，或用「已暂存的插件包」里的安装 |

## 6. 诊断证据在哪

| 位置 | 内容 |
| --- | --- |
| `<DSH_HOME>\plugin-drop\plugin-drop.log` | 本工具的流水：上下文解析、每次暂存、安装启动、操作结果（`→ done (exit 0)`）、被拒绝的请求与原因、删除暂存副本 |
| `<DSH_HOME>\profiles\<profile>\.plugin-manager\logs\operation-*\pnpm.log` | 官方操作的日志目录（走 CLI 适配器时输出直接回传到页面，这里可能是 0 字节） |
| `<DSH_HOME>\logs\desktop-next.log` | 应用自身日志（账号、UI 诊断等）。**本插件不写这里**，所以不要在这里找它 |
| 页面「环境」区块 | profile / profile 目录 / home / 暂存目录 / 诊断日志路径 / HTTP 路由 |
| `E:\dsh\home\profiles\desktop\package.json` | 最终真相：`dependencies` 与 `dsh.profile.bundles` 是否登记成功 |

## 7. 等价命令与回滚

```powershell
$app = "C:\Users\Lenovo\AppData\Local\Programs\DSH NEXT\resources\app"
$exe = "C:\Users\Lenovo\AppData\Local\Programs\DSH NEXT\DSH NEXT.exe"
$env:DSH_HOME = "E:\dsh\home"; $env:ELECTRON_RUN_AS_NODE = "1"

# 安装（等价于页面上的安装）：目录 / .tgz 都行
& $exe --expose-internals "$app\lib\plugin-cli.js" desktop add "C:\绝对\路径\到\插件目录"

# 卸载
& $exe --expose-internals "$app\lib\plugin-cli.js" desktop remove dsh-purge

# 卸载这个安装器本身
& $exe --expose-internals "$app\lib\plugin-cli.js" desktop remove dsh-plugin-drop
```

注意：路径安装会记成 `link:`，**暂存目录就是插件的常驻位置**，装好后不要删除它；
要清理请用页面上的「删除」按钮（会提醒已安装的插件会失效），或先卸载再删。
